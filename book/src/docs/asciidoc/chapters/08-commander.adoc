[#commander]
== Nasdanika Commander

[horizontal]
Capability:: Two panels over volumes with the classic keys: navigate, view, edit, copy, move, create and delete. Over the local file system it is a file manager for wherever the usual one is not installed. Over other volumes it is a way into whatever they hold.
Demonstration:: `CommanderTests` and `TerminalLoopTests` in `runtime/commander`. After the build, `java -jar` runs it.
Status:: [.sketch]#SKETCH# in `runtime/commander`: a working prototype with the minimum for daily file work.
Depends on:: <<terminal>>, the runtime's `volume` module, TamboUI {tamboui-version} and JLine.
Value and effort:: High for medium. It is used by its author first, and it is the first real consumer of the terminal modules.
How to help:: Use it for a day and report what you reached for and did not find. A volume of your own is the most interesting contribution: see <<commander-volumes>>.

=== Why

Anyone who used Norton Commander or FAR knows the screen: two panels, a bar of function keys, and hands that do not leave the keyboard.
That knowledge is decades old and still in the fingers, so the keys are kept as they were.

The reason to build one more is what the panels show.
A panel here is a `Volume`, the runtime's small file abstraction, and a directory on disk is only one kind of volume.
A zip file, a repository on a server, the modules of a running JVM and the elements of a model can all be volumes.
Wherever a volume exists, the commander is already its user interface, with no page to write and no server to run.

=== Running it

[source,text,subs="attributes"]
----
mvn -q package
java -jar runtime/commander/target/commander-{revnumber}.jar [left directory] [right directory]
----

Both panels start in the current directory unless told otherwise.
The jar's manifest names its dependencies in `target/lib`, which the build fills, and `commander` and `commander.cmd` beside the module's `pom.xml` run the same line.

=== What is not there yet

A list for a tool that is meant to be used.

* [.planned]#PLANNED# *Marking several entries,* with kbd:[Insert], and acting on all of them.
* [.planned]#PLANNED# *Progress and cancel* for a long copy, and keeping the time of last change on a copy.
* [.planned]#PLANNED# *Search* in a panel and in the viewer, and a viewer for files that are not text or are too large to hold.
* [.planned]#PLANNED# *A navigator with details:* one panel and, beside it, what the selected entry is, instead of a second panel. For a model that is the more useful form.
* [.planned]#PLANNED# *Any tree, with commands by type.* A panel over a generic volume of model elements or of the pages and shapes of a Draw.io file, where the commands offered depend on what is selected. Navigating a structure and acting on its elements is the polymorphic user interface in another form.
* [.planned]#PLANNED# *Extensions through the capability framework:* syntax highlighting, commands, and an assistant that can be asked about what is selected.
* [.planned]#PLANNED# *A command for scripts and agents* that runs an action on a path, so that what a person can do with a key, an agent can do with a line.
* [.planned]#PLANNED# *As a command of `nsdk`,* with the volumes that the commands before it on the line produce, and in an organization's own command line with its own volumes.
